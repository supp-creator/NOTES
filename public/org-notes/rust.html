Macros and #[Derive]

Macros are expanded during compilation into Rust code. The are indicated by a ! at the end. Functionally, they are code that writes other code. Which is knwon as metaprogramming.

#[derive] is used to implement traits for structs and enums. Traits such as Debug, Clone, Copy, PartialEq, Eq, Hash, Default, and stuff like that. These traits are already built-in or imported. 

  #[derive(Debug, Clone, PartialEq)]
  struct Point {
      x: f64,
      y: f64,
  }

  fn main() {
      let p = Point { x: 1.0, y: 2.0 };
      println!("{:?}", p);
    }

#[derive(Debug)] allows you to print a value with {:?} or {:#?}. Use this with println!.

#[derive(Clone, Copy)] allows you to explicitly duplicate value using .clone() and then copy it somewhere else. 

  #[derive(Clone, Copy)]
  struct Point {
      x: f64,
      y: f64,
  }

  fn main() {

      let a = Point { x: 1.0, y: 2.0 };
      let b = a;  // b copies a, not moved. This means a is still valid
      let c = a.clone(); // cloned
  }

The trait PartialEq let's you compare using == and !=. The trait Eq requires PartialEq and signals that equality is total ( every value equals itself ). FLoats cannot implement Eq due to NaN != NaN.

References

You may have many shared references but only one exclusive reference.

Shared References

A reference is a way to access another value without taking ownership of the value. This is called 'borrowing'. Shared references are read-only, the data cannot be changed. 

  fn main() {
      let a = 'A';
      let b = 'B';

      let mut r: &char  = &a;
      dbg!(r);

      r = &b;
      dbg!(r);
  }

A reference value is made with tehe & operator. The * operator dereferences a reference.

A shared reference to a type T has the type &T.

Rust can auto-dereference in many cases. 

  let mut s = String::from("hello");
  let c = &mut s;

  c.push_str(" world"); // no * needed, Rust auto-derefs for method calls
  println!("{}", s); // "hello world"

Exclusive References

Exclusive references are known as mutable references. They allow you to change the value they are refering to. 

  fn main() {

      let mut point = (1, 2);
      let x_coord = &mut point.0;
      *x_coord = 20;
      println!("point: {point:?}"); // Output=>  point: (20, 2)
  }

They have type &mut T.

Very similar to pointers. Create a variable and point it to the reference using &mut. Then make changes to that variable using &mut and the changes made to the new variable will reflect in the original variable.

Slices

A slice let's you view into a larger collection. 

  fn main() {

      let a: [i32; 6] = [10, 20, 30, 40, 50, 60];
      println!("a: {a:?}");

      let s: &[i32] = &a[2..4];
      println!("s: {s:?}");
  }

Slices borrow data.

If the slice starts at index 0, you may drop the starting index so it will be &a[..a.len()]

The same is true for the last index, so &a[2..a.len()] is the same as &a[2..].

To make a slice of the full array, use &a[..]

You cannot append to a slice since it doesn't own the backing buffer.

Strings

&str is a slice of UTF-8 encoded bytes. This is a string slice, an immutable reference to UTF-8 encoded string data stored in a block of memory. String is an owned buffer of UTF-8 encoded bytes. 

  fn main() {

      let s1: &str = "World";

      let mut s2: String = String::from("Hello ");
 
      s2.push_str(s1);
      println!("s2: {s2}"); //Outputs: Hello World

      let s3: &str = &s2[2..9];
      println!("s3: {s3}"); // Outputs: 'llo Wor'
  }

The String data type of Rust is a wrapper around a vector of bytes.

String::new() creates a new, empty string to which data can be added using the .push() and .pushstr() methods.

String::from() creates an owned, growable String from a literal string. 

  let s1 = String::from("hello");

  let s2 = "hello".to_string(); //same as s1
  
  let s3 = String::new() //empty string

The .push() method appends a single character (char).

The .pushstr() method appends a string slice (&str). 

  let mut s = String::from("hello");

  s.push('!'); // this is fine
  s.push("!"); //this is &str, not char so this will lead to an error

  s.push_str(" world");

Other useful String methods 

  let mut s = String::from("hello world");

  s.contains("world");                   // outputs true
  s.replaces("world", "rust");          // returns new String "hello rust"
  s.to_uppercase();                    // "HELLO WORLD"
  s.len();                            // 11 bytes since it uses 11 characters
  s.is_empty();                      // outputs false
  s.split(" ").collect::<Vec<_>>(); // ["hello", "world"]

In Rust, references are always safe to use due to certain rules.

One of the rules is that references can never be null.

References can't also outlive the data they point to.

Pattern Matching

Irrefutable Patterns

  fn takes_tuple(tuple: (char, i32, bool)) {
      
      let a = tuple.0;
      let b = tuple.1;
      let c = tuple.2;

      let (a, b, c) = tuple; //This does the same as the block above

      let (_, b, c) = tuple; //Ignores the first element, binds only the second and third.

      let (.., c) = tuple; //Ignores everthing but the last element
  }

  fn main() {
      takes_tuple(('a', 777, false));
  }

Irrefutable means that the patters will always match the value on the RHS.

Variable names are patterns that always match and bind the matched value into a new variable with that name.

Patterns are type-specific.

_ is a pattern that always matches any value, discarding the matched value.

.. allows you to ignore multiple values at once.

You may wonder what even is destructuring.

Destructuring is unpacking a data structure into its individual components in one field.

  //This is destructuring; just takes one line.
  let point = (3.0, 4.0);

Let Control Flow

if let expression

This lets you execute different code depending on whether a value matches a pattern. 

  use std::time::Duration;

  fn sleep_for(secs: f32) {

      let result = Duration::try_from_secs_f32(secs);

      if let Ok(duration) = result {
  	std::thread::sleep(duration);
  	println!("slept for {duration:?}");
      }
  }

  fn main() {
      sleep_for(-10.0);
      sleep_for(0.8);
  }

Unlike match, if let does not have to cover all branches.

This is used to hanlde Some values when working with Options.

Unlike match, if let does not support guard clauses for pattern matching.

With an else clause, this can be used as an expression.

while let statements

This repeatedly tests a value against a pattern. 

  fn main() {

      let mut name = String::from("Comprehensive Rust");

      while let Some(c) = name.pop() {
  	dbg!(c);
      }
  }

In this weird ass example to print out each character of a string in reverse order, String::pop returns Some(c) until the string is empty, after which it will return *None.

Wait, what the heck does Some() do?

Some() is a varaint of the Option enum. 

  enum Option<T> {
      Some(T),   // there IS a value, and this is it
      None,     // there is NO value
      
  }

T can be any type: Some(5), Some("hello"), Some(Point{…}), and such.

Rust has no null. If a value is absent, the type system will need you to handle it. 

  fn find_user(id: u32) -> Option<String> {
      if id == 1 {
  	Some(String::from("Alice")) // found a value
      } else {
  	None // There really is no value 
      }
  }

Anyway, while let loops will keep going so long as the value matches the pattern.

This cannot be used as an expression because they may have no value if the condition is false.

let else statement

If you're just matching a pattern and returning from the funtion, use let else. The else case must diverge into return, break, or panic - anything but falling off the end of the block. 

  fn hex_or_die_trying(maybe_string:Option<String>) -> Result<u32, String> {
      let Some(s) = maybe_string else {
  	return Err(String::from("got None"));
      };

      let Some(first_byte_char) = s.chars().next() else {
  	return Err(String::from("got empty string"));
      };

      let Some(digit) = first_byte_char.to_digit(16) else {
  	return Err(String::from("not a hex digit"));
      };

      Ok(digit)
  }

So, Result is the same with Option but for error handling. 

  enum Option<T> {
      Some(T),
      None,
  }

  enum Result<T, E> {
      Ok(T),     // success, has a value 
      Err(E),   // failure, has an error
  }

  fn divide(a: f64, b: f64) -> Result<f64, String> {
      if b == 0.0 {
  	Err(String::from("cannot divide by zero"))
      } else {
  	Ok(a / b)
      }
  }

  match divide(10.0, 2.0) {
      Ok(result) => println!("quotient: {}", result),
      Err(e) => println!("oops: {}", e),
  }

E type can be anything: a string message, io::Error, ParseError. 

  Result<f64, String>;  // If successful,  expect a float. Otherwise, a string.

  Result<u32, io::Error>;

  Result<(), ParseError>;   // T is () - success has no value, just that it 'works'

Methods

  // Copyright 2023 Google LLC
// SPDX-License-Identifier: Apache-2.0

#[derive(Debug)]
struct CarRace {
    name: String,
    laps: Vec<i32>,
}

impl CarRace {
    // No receiver, a static method
    fn new(name: &str) -> Self {
        Self { name: String::from(name), laps: Vec::new() }
    }

    // Exclusive borrowed read-write access to self
    fn add_lap(&mut self, lap: i32) {
        self.laps.push(lap);
    }

    // Shared and read-only borrowed access to self
    fn print_laps(&self) {
        println!("Recorded {} laps for {}:", self.laps.len(), self.name);
        for (idx, lap) in self.laps.iter().enumerate() {
            println!("Lap {idx}: {lap} sec");
        }
    }

    // Exclusive ownership of self (covered later)
    fn finish(self) {
        let total: i32 = self.laps.iter().sum();
        println!("Race {} is finished, total lap time: {}", self.name, total);
    }
}

fn main() {
    let mut race = CarRace::new("Monaco Grand Prix");
    race.add_lap(70);
    race.add_lap(68);
    race.print_laps();
    race.add_lap(71);
    race.print_laps();
    race.finish();
    // race.add_lap(42);
}

The self arguement specifies the object the method acts on (the 'receiver').

It could be &self which borrows the object from the caller using a shared and immutable reference. The object can be used again later.

It could be &mut self which borrows the object from the caller using a unique and mutable reference. The object can be used again later.

It could be self which takes ownership of the object from the caller. The method becomes the new owner of the object. The object will be deallocated or 'dropped' when the method returns, unless ownership is explicitly transmitted.

It could be mut self which is the same as above, taking new ownership, but the method can mutate the object.

No receiver is also an option. This is usually used to create constructors that are called new by convention.

Methods are called on an instance of a type such as a struct or enum. The first parameter represents the instance as self.

self, the method receiver, is abbreviated for self: Self.

Self is a type alias for the type tje impl blcok is in and can be used elsewhere within the block.

Basically, self refers to the instance. Self refers to the type.

Traits

Traits are used to abstract over types, similar to interfaces. 

  trait Pet {

      fn talk(&self) -> String;

      fn greet(&self);
  }

Traits defines a number of methods that types must have in order to implement the trait.

Implementing traits

    trait Pet {
        fn talk(&self) -> String;

        fn greet(&self) {
    	println!("Oh, what's your name? {}", self.talk());
    	
        }
  }

  struct Dog {
      name: String,
      age: i8,
  }

  impl Pet for Dog {
      fn talk(&self) -> String {
  	format!("Woof, my name is {}!", self.name)
  	    
      }
   }

  fn main() {
      let fido = Dog { name: String::from("Fido"), age: 5 };
      dbg!(fido.talk());
      fido.greet();
      
  }

To implement Trait for Type, use an impl Trait for TYpe { .. } block.

Unlike in Go interfaces, just having matching methods is not enough: a Cat type with a talk() method would not automatically satisfy Pet. Unless it is in an impl Pet block.

Associated Types

These are placeholder types that are supplied by the trait implementation. 

     #[derive(Debug)]
     struct Meters(i32);

     #[derive(Debug)]
     struct MetersSquared(i32);

     trait Multiply {

         type Output = MetersSquared;

    	fn multiply(&self, other: &Self) -> Self::Output;
    }

    impl Multiply for Meters {
        type Output = MetersSquared;

    	MetersSquared(self.0 * other.0)

  }

Associated types are sometimes called 'output types'.

It is important to note that the implementer, not the caller, chooses this type.

Generics

Generics lets you abstract algorithms or data structures over the types used or stores. 

  fn pick<T>(cond: bool, left: T, right: T) -> T {
      if cond { left } else { right }
  }

  fn main() {
      println!("pick a number: {:?}", pick(true, 222, 333));
      println!("pick a string: {:?}", pick(false, 'L', 'R'));
  }

This can be used for stuff like sorting or a binary tree.

Genercis can reduce code duplication; letting you write code that works for any type. This is essentially what Options<Some, None> and Result<Ok, Err> are.

Generic Functions

Instead of: 

fn largest_i32(list: &[i32]) -> i32 {
    let mut largest = list[0];
    for &item in list {
        if item > largest { largest = item; }
    }
    largest
}

fn largest_f64(list: &[f64]) -> f64 {
    let mut largest = list[0];
    for &item in list {
        if item > largest { largest = item; }
    }
    largest
}

You can just: 

  fn largest<T: PartialOrd>(list: &[T]) -> T {
      let mut largest = list[0];
      for &item in list {
  	if item = largest { largest = item }
      }
      largest
  }


  largest(&[1, 2, 3, 4]);  //i32
  largest(&[1.0, 2.0, 3.0, 4.0]); //f64

Trait bounds - constraining what T can be

Without bounds, T could be anything. Trait bounds say "T must implement this trait" 

  use std::fmt::Display;

  // T must implement Display trait if it is to be printed
  fn print_value<T: Display>(value: T) {
      println!("{}", value);
  }

  // T must implement Display and Clone traits to use this function
  fn print_and_clone<T: Display + Clone>(value: T) {
      let copy = value.clone();
      println!("{}", copy);
  }
Generics Meaning
<T> placeholder for any type
<T: Trait> T must implement this trait
<T: Trait + Trait> T must imlplemnt these traits
<T, U> multiple type placeholders
   

Closures

Anonymous functions that can store variables or be passed to other functions. It is enclosed in | |. 

  fn add(a: i32, b: i32) -> i32 { a + b }

  let add = | a, b| a + b;      // same as above.

Regular functions can't use variables from the surrounding scope. But closures can. This is called capturing. The closure "closes over" the variable. 

  let x = 10;

  let add_x = |n| n + x; // captures x from outside
  println!("{}", add_x(5)); // outputs 15

Closures can capture by referencing &T, this is the default and just reads the value. 

  let name = String::from("Alice");

  let greet = || println!("hello {}", name); // borrows name variable

  greet();
  
  println!("{}", name); // name still usable

By mutable reference &mut T: 

  let mut count = 0;

  let mut increment = || count += 1; //mutably borrows count

  increment();

  increment();

  println!("{}", count); // outputs 2

By ownership with move: 

  let name = String::from("Alice");

  let greet = move || println!("hello {}", name); // takes ownership of name

  greet(); // name variable is gone. "Alice" has been moved into the closure.

Examples: 

  let numbers = vec![1, 2, 3, 4, 5];

  let doubled: Vec<i32> = numbers:iter()
      .map(|n| n * 2)
      .collect(); // [2, 4, 6, 8, 10]

  let evens: Vec<i32> = numbers:iter()
      .filter(|n| *n % 2 == 0)
      .collect(); // [2, 4]

  let first_even = numbers.iter()
      .find(|n| *n % 2 == 0); // Some(2)

  let sum = numbers.iter().fold(0, |acc, n| acc + n); // 15

  let result: Vec<i32> = numbers.iter()
      .filter(|n| *n % 2 ==0)
      .map(|n| n * 10)
      .collect(); // [20, 40]

  // As a function argument

  fn apply(f: impl Fn(i32) -> i32, value: i32) -> i32 {
      f(value)
  }

  let double = |n| n * 2;

  println!("{}", apply(double, 5)); // 10

There are three traits for closure.

Fn borrows immutably, can be called many times.
FnMut borrows mutably, can be called many times.
FnOnce takes ownership, can only be called once.
   

Ownership

Every variable in Rust has exactly one owner at a time.

When the owner goes out of scope, the value is automatically dropped (freed).

Ownership can be transferred, this is called a move. 

  let s1 = String::from("hello");
  let s2 = s1; // ownership of "hello" moves from s1 to s2.

  println!("{}", s1); // Error since s1 no longer owns any value.

  println!("{}", s2); // "hello"
